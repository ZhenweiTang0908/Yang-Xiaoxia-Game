# 本项目的范例：第三、第四位 Boss

用户认为这两位最成功。这里记录的是**它们为什么能成立**，用来校准判断，不是模板。新 Boss 不应该看起来像它们中的任何一个。

## 噬月祭主（第三战，`data/bosses/priest.tres`，`scripts/actors/boss.gd`）

十招、3600 生命，在 65% 和 30% 生命时变换阶段（迎月 → 月蚀初临 → 噬月终仪）。

成立的原因：

- **每一招问的问题不同**。直线冲刺要离开那条线，地裂波要跳，落雷要持续移动，环形幽火要找到缺口，追魂弹要看弹道，悬刃雨和噬月大阵要找安全区，裂隙换位斩要离开被锁定的位置。十招对应七八种回答，所以十招不显得多。
- **永远有出路**。环形幽火故意留下一个可见的缺口（代码里有注释），悬刃雨和大阵的安全区根据玩家位置生成，并且在第二波移位。压力很大，但不会不公平。
- **人物和招式一致**。祭司不擅长近身肉搏，所以大部分压力来自场地和法术，近身只有冲阵和四连斩，读起来就是“一个在主持仪式的人”。
- **阶段改变节奏**。阶段之后招式顺序反转、冷却缩短，阶段转换时清场并留出重新站位的时间。

## 断誓枪骑（第四战，`scripts/actors/knight*.gd`，`docs/knight-*.md`）

马战 2400 加步战 2400，半血下马。

成立的原因：

- **阶段改变身体**。马战和步战是两种完全不同的身体：前者是马的冲量、蹄子和长枪的距离，后者是人的步法、枪尾、弓。下马本身是一个有代价、有画面的事件，而不是数值切换。
- **预兆只来自身体**。没有危险矩形、感叹号、倒计时或招式名，读招靠抬手、蹬地、拉弦的声音、金紫色的蓄势。玩家学会的是“看人”，而不是“看界面”。
- **承诺和判定都诚实**。冲锋承诺后不转向；只有枪尖结算；近身招先突进到有效距离再出手；箭在放箭前才锁定，锁定后不再追。
- **防重复但能学习**。选招时优先最近没用过的有效候选，长连段之间至少隔一个其他技能，同一招不会连用三次。
- **压力有来源也有上限**。战怒由 Boss 受到的伤害积累，玩家打得越狠，回报越大，危险也越大；幽军数量、虚像数量都有上限，避免画面失控。用户曾删掉无法躲避的全屏紫鹰，这说明了用户的底线。
- **和主角的系统互动**。箭封葫芦、幽军与牛大侠的互动，让这场战斗不只是羊小侠一个人和 Boss 的事。但每种封锁都有时长上限，并且重复封锁取较长者而不叠加。
- **人物有声音**。55 句台词覆盖登场、下马、重要技能、低血量和败北，“断誓”的身份在台词里，不在 HUD 上。
- **一切可调、一切可测**。突进速度、前摇、伤害倍率、战怒比例、封禁时长都在 F2 面板；每轮改动都有测试和真实渲染截图记录（见 `docs/knight-*.md` 的验证记录）。

## 从两者共同抽出的判断标准

1. 招式数量本身不重要，**不同回答的数量**才重要。
2. 压力可以很大，但每一刻都必须有可以读到的出路。
3. 招式要从人物身上长出来；阶段变化要是人物的变化。
4. 预兆、判定、承诺都要对玩家诚实。
5. 数值能调，行为能测，画面要截图给用户确认。
