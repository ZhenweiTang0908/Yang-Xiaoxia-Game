# 跑步步幅与原画审计

run_stride_audit 在 225 像素/秒下测量原有支撑脚锚点，一次支撑期间世界坐标漂移约 26–34 像素。位置插值不解决这一问题。

tests/hero_stride_experiment.gd 是独立后蹬／抬脚实验：步态周期 0.42 秒、支撑脚线性向后移动、摆动脚抬起前送。测试锚点漂移为零，但这不是像素脚掌贴地与腿部比例正确的证明，尚未接入正式角色。实验文件留在 tests 中，不随导出交付。

逐张检查发现 hero_2d/hero/08.png 和 09.png 原画均含两把剑。正式跑步循环使用 10–15 六张单剑姿势，在 0.56 秒内均匀分配并闭合至 10，不重复停留在 15。原始图片保持不变。这避免异常武器，但不等于步幅问题已解决；仍需补画可靠的过渡姿势。

## 支撑顺序与脚掌蒙皮修正

正式顺序调整为 10、13、14、11、12、15：前三帧前脚支撑，后三帧后脚支撑。原数字顺序在一循环内切换四次支撑，和两次脚步节奏不符。脚掌附近蒙皮改为局部刚性、脚踝向上渐变；六张姿势中 38 个脚掌核心顶点检查通过。头、衣领和腿部不受衣摆跟随影响的检查仍通过。

重新测量的完整支撑区间锚点世界漂移约 58–61 像素；支撑时间变长，所以不能直接以旧 26–34 的区间总量比较。这明确说明后蹬位移仍不足，当前改动解决支撑切换节奏和脚掌局部变形，没有解决真实世界锁脚。仍需重新设计匹配移动速度的腿部姿势，不能声称已达到最终流畅质量。

## 身体标注复核

使用 tests/run_guides_visual.gd 将六个身体点叠加到 10–15 独立原画，明确计入裁切 offset -28。旧髋点过低，12/15 握点和部分脚点位于轮廓外。现重新标注髋、手和脚，保持头颈点不变，并重新生成脚底坐标 JSON。叠加结果在 builds/qa/run-guides.png。

主角 17 项、30/60/120 FPS 落脚时序、衣摆范围检查通过；重新录制并检查 0070/0085 跑步帧。世界漂移仍为约 49–68 像素/完整支撑区间，未解决滑步。新标注为进一步膝关节和步幅设计提供可靠支点，不能据此宣称动作已经完全流畅。
